# LabelSense — автоматическая проверка маркировки, комплаенса и трассировки

*Гарантируем правильную этикетку, штрихкод и соответствие регуляторным требованиям — до момента отправки.*

---

# Слайд 1 — TL;DR (1–2 предложения)

**Проблема:** неправильная маркировка и несоответствие регламентам приводят к штрафам, отзыву партий и репутационным потерям.
**Решение:** LabelSense — комплексное решение: визуальная и семантическая проверка этикеток, валидация соответствия стандартам, автоматическая привязка к партии и документации.

*Заметки выступающего:* начинать с реального кейса: отзыв партии лекарств или штраф от ритейлера из-за неправильной этикетки.

---

# Слайд 2 — Детализированная проблема

* Ошибки в тексте этикетки (неправильные ингредиенты, дозировки, предупреждения).
* Неправильный язык/локализация на экспортных поставках.
* Нечитаемые/повреждённые штрихкоды, неправильные форматы GTIN/SSCC.
* Несоответствие регуляторным требованиям (дата истечения, серийные номера, GMO-метки и т.п.).
* Сложности трассировки при отзыве: ручной поиск по WMS/бумажкам — длительный процесс.

*Заметки выступающего:* подчеркни финансовые и юридические риски — штрафы, recall costs, downtime.

---

# Слайд 3 — Что такое LabelSense (концепция)

* Камеры + OCR + семантический парсер этикеток.
* B2B-платформа для проверки соответствия локальным/международным требованиям.
* Интеграция с ERP/WMS/ERP для валидации партий и документов.
* Модуль трассировки: от сырья до отправки — все связки в единой истории.

*Заметки выступающего:* это не просто OCR — это проверка смысла и соответствия правилам, а также автоматический след действий при несоответствии.

# Слайд 4 — Ключевые кейсы использования

1. Валидация фармэтикеток: дозировка, предупреждения, регистрационные номера.
2. Проверка языковой версии и локализации для экспорта.
3. Аудит упаковки для FBA/retail форматных требований.
4. Быстрая трассировка и подготовка к отзыву партии.
5. Автоматическое создание compliance-отчётов для регуляторов.

*Заметки выступающего:* выделяй отрасли: фарма, пищепром, COS (косметика), FBA-поставщики.

# Слайд 5 — Продуктовые функции (подробно)

* Мультистрочный OCR с полем валидации (настроить regex/правила).
* Семантический парсер: извлечение ингредиентов, доз, предупреждений, серийных номеров.
* Штрихкод-валидатор: проверка стандартов (GS1), читаемости и соответствия SKU.
* Правила комплаенса: шаблоны для стран/ретейлеров, валидируемые автоматически.
* Трассировка партии: горячая кнопка “recall” с экспортом всех связанных записей.
* Audit log и e-sign для операторов.

*Заметки выступающего:* покажи, как легко добавлять новые правила под конкретный рынок или клиента.

# Слайд 6 — Демонстрация процесса (demo flow)

1. Упаковка проходит под камерой → изображение фиксируется.
2. OCR + semantic engine извлекают ключевые поля (LOT, EXP, INGREDIENTS).
3. Правила проверяют соответствие (например, "наличие предупреждения на языке страны").
4. Результат: OK → штамп и запись в ERP; FAIL → Hold + подробный отчёт и рекомендуемые действия.
5. Если FAIL — запускается процедура трассировки и уведомления ответственных.

*Заметки выступающего:* опиши SLA реакции: визуальная проверка + решение оператора < 2 минуты.

# Слайд 7 — Технология и архитектура

* Камеры (RGB) + edge-инференс для OCR/детекции.
* Сервис правил (rules engine) в облаке/локально — гибкие политики.
* Semantic engine (NER + dependency parsing) для извлечения смысловых сущностей.
* Интеграции: API/Webhooks для ERP/WMS, message bus для событий.
* Data lake для хранения изображений и audit-trails (с политиками retention).

*Заметки выступающего:* опиши баланс: минимальные данные на облаке, конфиденциальность критических полей.

---

# Слайд 8 — ML-пайплайн и качество моделей

* Data collection: реальные фото и синтетика (шумы, смещения, разные принтеры).
* Модели: OCR (CRNN/Transformer), NER для этикеток (fine-tuned), классификатор читабельности штрихкодов.
* Active learning: операторы правят ошибки — данные автоматически попадают в тренировочный пайплайн.
* Метрики: CER/WER для OCR, F1 для NER, barcode decode rate, latency.
* Целевые значения для пилота: OCR CER < 2–4% на ключевых полях; decode rate > 98%.

*Заметки выступающего:* честно говори, что реальные цифры зависят от материалов, шрифта и освещения.
